# GeoSafe-FIS API Contract

## 1. Conventions

- Base path: `/api/v1`.
- Transport: JSON over HTTP, except for PDF report responses.
- Coordinates: WGS 84 (`EPSG:4326`). Query endpoints accept either `latitude`/`longitude` or the aliases `lat`/`lon`. GeoJSON coordinates remain `[longitude, latitude]`.
- Assessment creation accepts coordinates either at the top level or inside a `location` object.
- Times generated by SQLite use its UTC timestamp format. Source dates may be date-only or absent.
- Authentication: none in the initial prototype.
- History pagination uses `limit` and `offset`; it does not use page numbers.

There are no authentication, account, user, role, permission, staff, administration, approval, audit, upload, or model-editing routes. A future shared environment-variable password, if separately approved, would protect the whole application and is not implemented.

## 2. Common fields and errors

### 2.1 Provenance and quality

Imported boundary, hazard, incident, and CLUP records expose their applicable source metadata together with:

- `is_official`: Boolean;
- `is_demo`: Boolean;
- `data_status`: `official` or `demonstration`; and
- hazard-dataset `quality_status`: `verified`, `provisional`, `limited`, or `unknown`.

The importer requires every dataset to be explicitly classified as `official` or `demonstration`. It does not infer official status. Live ULAP responses separately expose endpoint verification, agency/attribution, layer/field, retrieval/cache state, and point-level availability.

Live source statuses include `available`, `no_intersection`,
`outside_coverage`, `unavailable`, `authentication_required`, `service_error`,
`timeout`, `invalid_response`, `changed_schema`, and
`pending_verification`. Metadata validation also uses `verified`,
`verified_with_changed_metadata`, `inaccessible`, `invalid_layer`, and
`missing_classification_field`.

Saved assessment inputs retain a compatible `availability_status` of
`available` or `missing`; the specific live status/reason remains in their
source snapshot. Missing is never converted to zero or low vulnerability.

Live hazard values retain:

- `raw_code` and unchanged `official_label`;
- `raw_attributes` and domain-decoded attributes;
- a separate `normalized_value` from the exact model-version lookup, when
  valid; and
- transformation/model validation notes.

Authorized imported hazards may additionally expose `normalized_fraction`
from 0–1 and a `normalized_value` equal to that fraction multiplied by 100.

### 2.2 Error object

```json
{
  "error": {
    "code": "validation_error",
    "message": "Query parameter 'latitude' must be numeric."
  }
}
```

Some errors include `details`, such as an `outside_basey` error containing the identified location. The implementation does not add a request/correlation ID to API errors. Common codes include `validation_error`, `outside_basey`, `not_found`, `data_unavailable`, `method_not_allowed`, and `internal_error`.

## 3. Live ULAP endpoints

### `GET /ulap/status?refresh={boolean}`

Returns runtime validation for all registered services:

```json
{
  "status": "degraded",
  "complete_assessment_available": false,
  "checked_at": "2026-07-23T09:00:00+00:00",
  "services": [],
  "required_failures": [],
  "notice": "Service availability is reported independently. A required hazard failure blocks the three-hazard score."
}
```

`refresh` defaults to `false`. `refresh=true` clears the process cache before
requesting fresh service/layer metadata. The current overall status is
`degraded` because required ground shaking is unavailable.

Each service validation includes `service`, `status`, `required`, sanitized
`source_url`, `checked_at`, `message`, `differences`, metadata/cache details,
HTTP status, and ArcGIS error code when present.

### `GET /ulap/services`

Returns the five version-controlled service definitions and their current
runtime validation:

```json
{
  "items": [],
  "count": 5,
  "manifest_audit": {}
}
```

Items cover flood, liquefaction, ground shaking, municipal boundary, and
barangay boundary. An unconfigured service has no active URL. Hazard items
include their expected classification domain and a backend display URL when
geometry is available.

### `GET /ulap/services/{key}/metadata`

Accepted keys are the exact registry keys:

```text
flood
liquefaction
ground_shaking
municipal_boundary
barangay_boundary
```

The endpoint performs current validation for that service and returns:

```json
{
  "service": {},
  "validation": {}
}
```

An unknown key returns `404 not_found`. No token or token-bearing query URL is
returned.

### `GET /hazards/at-location`

Requires `latitude`/`longitude` or `lat`/`lon` and returns all required source
results plus the pre-model completeness gate:

```json
{
  "location": {
    "latitude": 11.282,
    "longitude": 125.068,
    "inside_basey": true,
    "insideBasey": true,
    "barangay": {}
  },
  "hazards": {
    "flood": {},
    "liquefaction": {},
    "groundShaking": {}
  },
  "assessment": {
    "status": "incomplete",
    "assessmentStatus": "incomplete",
    "score": null,
    "category": null,
    "memberships": {},
    "activatedRules": [],
    "missingInputs": ["ground_shaking"],
    "message": "A complete assessment cannot be calculated because verified values are unavailable for: ground_shaking."
  },
  "sources": [],
  "dataQuality": [],
  "retrievedAt": "2026-07-23T09:00:00+00:00"
}
```

An available hazard object contains `raw_code`, `official_label`,
`classification_field`, full raw/decoded attributes, agency/service/layer,
source URL, CRS, source/retrieval date, attribution, feature count, warnings,
cache metadata, and the separate model transformation. This route runs the
fuzzy engine only when all normalized inputs exist; it currently returns an
incomplete result.

### `GET /hazards/{hazard}`

Accepted path values are `flood`, `liquefaction`, and `ground-shaking`. The
route requires coordinates and returns the corresponding point-source object.
`ground-shaking` maps internally to `ground_shaking` and currently returns
`unavailable`.

These point routes are distinct from map-geometry routes. A valid
zero-feature response is `no_intersection`, never Low.

## 4. Map and location endpoints

### `GET /boundary` and `GET /boundary/basey`

Equivalent routes returning the live PSA Basey municipal GeoJSON through the
backend. The FeatureCollection also includes `status`, `dataset` source/cache/
filter metadata, and `notices`. In normal server mode it does not fall back to
a demonstration extent.

### `GET /barangays`

Returns the 51 live PSA Basey barangay polygons as a paginated backend-fetched
GeoJSON FeatureCollection with source/cache metadata and notices. The current
route is Basey-filtered and has no caller-supplied bounding-box or
simplification parameters.

### `GET /barangays/{id}`

Returns one live barangay GeoJSON feature. The numeric path value is matched
against available feature/object, barangay, or PSGC identifiers.

### `GET /hazard-layers`

Returns:

```json
{
  "items": [],
  "required_hazard_types": [
    "flood",
    "liquefaction",
    "ground_shaking"
  ],
  "notices": []
}
```

In normal server mode, each item is derived from the live ULAP registry and
includes the service/layer, hazard type, agency, verification status,
configured domain, and availability. Ground shaking remains listed but
unavailable.

### `GET /hazard-layers/{id-or-slug}/features`

Returns a live GeoJSON `FeatureCollection`, `status`, source/domain/cache
`dataset` object, and `notices`. `{id-or-slug}` is one of the three hazard
keys. The backend obtains the live Basey municipal extent, queries only that
envelope with pagination, and adds the current official domain label to each
feature. It does not attach a GeoSafe-FIS normalized model value to source map
geometry.

The ground-shaking response is an empty FeatureCollection with
`status: "unavailable"` until a verified endpoint is configured.

### `GET /location/search?q={text}&limit={n}`

Searches live PSA Basey barangay names/PSGC codes and WGS 84 coordinate pairs
written as `latitude, longitude`. Search text must contain at least two
characters. The limit defaults to 10 and must be 1–50.

The prototype does not call a third-party geocoder. The response states that its scope is the loaded Basey data:

```json
{
  "query": "example",
  "items": [],
  "scope": "Live PSA ULAP Basey barangays and WGS84 coordinate pairs",
  "notice": "..."
}
```

### `GET /location/identify`

Required query coordinates can use either:

```text
?latitude=11.282&longitude=125.068
```

or:

```text
?lat=11.282&lon=125.068
```

The live response includes both snake-case and selected compatibility fields:

```json
{
  "latitude": 11.282,
  "longitude": 125.068,
  "inside_basey": true,
  "status": "available",
  "municipality": "Basey",
  "province": "Samar",
  "municipal_boundary": {
    "id": "086002000",
    "name": "Basey, Samar",
    "is_official": true,
    "is_demo": false,
    "source_metadata": {}
  },
  "barangay": {
    "id": "086002035",
    "name": "Buscada (Pob.)",
    "psgc_code": "0806002035",
    "is_official": true,
    "is_demo": false,
    "source_metadata": {}
  },
  "notices": []
}
```

The municipal query runs first. A non-Basey/no-municipal result is outside
coverage. Multiple Basey or barangay polygons produce warnings. If no
barangay is returned for an inside-Basey point, `barangay` is null and status
is `no_intersection`.

## 5. Assessment endpoints

### `POST /assessments`

All of these coordinate shapes are accepted:

```json
{"latitude": 11.282, "longitude": 125.068}
```

```json
{"lat": 11.282, "lon": 125.068}
```

```json
{
  "location": {
    "latitude": 11.282,
    "longitude": 125.068,
    "display_label": "Optional label",
    "selection_method": "search"
  },
  "model_version": "0.4.0-demo"
}
```

`location_label` and `selection_method` are also accepted at the top level. `selection_method` defaults to `coordinates` and must be `search`, `coordinates`, or `map_click`; it is preserved in the saved location snapshot. If `model_version` is supplied, it must equal the active version. An outside-Basey point returns `422 outside_basey`; a valid assessment returns `201` and a `Location` header.

In normal server mode, the location and hazards come from live ULAP providers.
Repository demonstration records are rejected. The current source set produces
an incomplete saved assessment because ground shaking is unavailable.

The response is the saved assessment snapshot with links:

```json
{
  "id": 1,
  "created_at": "2026-07-23 08:00:00",
  "status": "incomplete",
  "location": {},
  "hazards": [
    {
      "hazard_type": "flood",
      "availability_status": "available",
      "classification": "High Susceptibility",
      "official_label": "High Susceptibility",
      "raw_code": "03",
      "classification_field": "fscode",
      "raw_attributes": {},
      "normalized_fraction": 0.75,
      "normalized_value": 75.0,
      "model_transformation": {
        "official_value": {
          "code": "03",
          "label": "High Susceptibility"
        },
        "normalized_value": 75,
        "model_version": "0.4.0-demo",
        "notice": "This normalized index is a GeoSafe-FIS model transformation, not an official agency numerical rating."
      },
      "source": {},
      "warnings": [],
      "quality_notice": null
    }
  ],
  "result": {
    "status": "incomplete",
    "model_version": "0.4.0-demo",
    "normalized_inputs": {},
    "memberships": {},
    "evaluated_rules": [],
    "activated_rules": [],
    "centroid": null,
    "score": null,
    "category": "Incomplete",
    "missing_inputs": ["ground_shaking"],
    "inference": {},
    "validation_notes": [],
    "message": "Required hazard input is unavailable."
  },
  "historical_incidents": [],
  "clup_references": [],
  "source_information": {},
  "data_sources": [],
  "data_quality_notices": [],
  "recommendations": [],
  "disclaimer": "...",
  "report_preview": {
    "sections": [],
    "format": "PDF",
    "download_url": "/api/v1/assessments/1/report"
  },
  "links": {
    "self": "/api/v1/assessments/1",
    "explanation": "/api/v1/assessments/1/explanation",
    "report": "/api/v1/assessments/1/report"
  }
}
```

For live evidence, `normalized_fraction` is only the compatibility rendering
of the configured GeoSafe-FIS model index divided by 100. It is not an
official source value. `model_transformation` is the authoritative explanation
of how the raw code entered this model version.

`evaluated_rules` contains all 12 rules, including zero activations. `activated_rules` contains only rules whose weighted `activation` is greater than zero. Each rule exposes `raw_activation`, `weight`, weighted `activation`, conditions and their memberships, consequent, statement, and rationale.

For missing required hazard data:

- top-level and result `status` are `incomplete`;
- the hazard retains its specific source status, such as
  `no_intersection`, `unavailable`, or `changed_schema`, and has null
  normalized values;
- `result.score` and `result.centroid` are null/absent;
- `result.category` is the status label `"Incomplete"`, not a vulnerability category;
- `missing_inputs` lists the unavailable variables; and
- no rules appear in `activated_rules`.

### `GET /assessments?limit={n}&offset={n}`

Returns unified, non-user-scoped assessment history:

```json
{
  "items": [],
  "count": 0,
  "limit": 50,
  "offset": 0
}
```

`count` is the total saved assessment count. `limit` defaults to 50 and must be 1–100; `offset` defaults to 0 and cannot be negative.

### `GET /assessments/{id}`

Returns the saved assessment source snapshot plus current convenience links. Later imports or model changes do not recalculate it.

### `GET /assessments/{id}/explanation`

Returns the saved result’s model version, normalized inputs, memberships, all evaluated rules, activated rules, inference metadata, centroid, score, category/status label, missing inputs, message, and validation notes.

### `GET /assessments/{id}/report`

Regenerates an `application/pdf` report from the immutable saved assessment snapshot on each request. It does not redo the spatial lookup or fuzzy assessment. Each generation records the snapshot and SHA-256 digest in `generated_reports`; the response includes `X-Report-SHA256` and a controlled attachment filename.

## 6. Context and methodology endpoints

### `GET /incidents?limit={n}`

Returns `{"items": [...], "count": n}` for available incident records. The default limit is 200 and accepted values are 1–1000. The current endpoint has no date, hazard, barangay, offset, or bounding-box filters.

### `GET /incidents/nearby`

Requires coordinate aliases described above. Optional parameters are:

- `radius_km`, default 10 and maximum 100;
- `radius_m`, which takes precedence after conversion to kilometres; and
- `barangay_id`.

Returns `items` and `count`. Each match adds `match_reason` (`same_barangay`, `covering_geometry`, or `within_radius`) and `distance_km` when point coordinates are available.

### `GET /clup-references?limit={n}`

Returns `items` and `count`. The default limit is 200 and accepted values are 1–1000. There are no other current filters.

### `GET /clup-references/by-location`

Requires coordinate aliases and optionally accepts `barangay_id`. Each returned record adds `match_reason`: `same_barangay`, `covering_geometry`, or `municipality_wide`.

### `GET /methodology`

Returns:

- `model`: the complete public `0.4.0-demo` configuration, version/checksum, normalization contract, input aliases, output-category details, and inference settings;
- `model_checksum`; and
- `scope`: purpose, numerical hazard inputs, context-only incident/CLUP data, and unified-access statement.

### `GET /data-sources`

Returns both a flattened catalogue and structured groups:

- `items`: flattened ULAP, supplied-reference, incident, CLUP, and model source
  entries;
- `official_data_availability`: one explicit status for every registered ULAP
  source plus incident and CLUP requirements;
- `ulap_services`: typed definitions with runtime validation;
- `supplied_manifest_audit`: checksum/structure/readiness facts for the
  unverified local JSON;
- `historical_incidents` with record count and `contains_demo: false`;
- `clup_references` with record count and `contains_demo: false`;
- `fuzzy_model` with version, checksum, status, and validation notes; and
- a notice that operational boundaries/hazards come from configured ULAP
  services and no synthetic runtime hazard is permitted.

## 7. Contract invariants

The current standard-library `unittest` suite verifies the core contract:

1. Registry, allowlist, metadata, ArcGIS errors, domains, cache/retries, point
   edge cases, and providers work against sanitized fixtures.
2. Live-source routes preserve raw official values and return explicit
   unavailable/schema/coverage states.
3. Complete fixture assessments expose all three hazards, memberships, 12
   evaluated rules, activated rules, a bounded integer score, sources/context,
   recommendations, disclaimer, and links.
4. A missing required hazard returns its specific missing status, an
   incomplete result, null score, and no activated rules; missingness is not
   interpreted as low.
5. Saved assessment history uses `limit`/`offset` and has no user or role scope.
6. PDF responses are valid, carry a SHA-256 header, and create a
   generated-report record.
7. Normal server mode rejects repository demonstration hazards; isolated
   fixture mode requires explicit test opt-in.
8. The real HTTP server serves the unified page and returns 404 for an
   administrative route.
9. Prohibited identity and administration endpoints are absent.

Static frontend contract tests additionally verify that only approved pages and API groups are referenced. They are not a browser-automation suite; interactive map behavior still requires the manual acceptance checks listed in [acceptance-criteria.md](acceptance-criteria.md).
